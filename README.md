# Масштаб — лабораторная работа №1 по РИП

Каталог издержек по теме «Оценка экономии от масштаба». Кофейные позиции используются как наглядные примеры, но предметная сущность приложения — издержка. Вместо суммы у каждой издержки указан числовой код счёта затрат по Плану счетов бухгалтерского учёта.

В ЛР1 реализованы только просмотр и серверная фильтрация: без базы данных, авторизации, сохранения формы и JavaScript.

## Требования лабораторной

- FastAPI и Jinja2 формируют три HTML-страницы тремя GET-обработчиками.
- Одна Python-коллекция содержит опубликованные издержки и один черновик.
- Медиа каждой издержки хранится в MinIO двумя отдельными URL.
- Интерфейс фиксированного размера 360 × 704 px и не перестраивается при изменении окна.
- Контент занимает 360 × 640 px, панель из трёх вкладок находится снизу и занимает 64 px.
- Вертикальное видео в ленте запускается автоматически; вся информация находится поверх видео.
- CSS вынесен в отдельный файл, JavaScript не используется.

## Экраны и адреса

| Страница | Адрес | Возможности |
|---|---|---|
| Лента | `/expenses/feed` | Вертикальное видео, двухстрочное описание с «Ещё», лайки, раскрываемые параметры и переход к следующей карточке. |
| Добавление | `/expenses/draft` | Поля черновика и превью медиа без кнопки сохранения или публикации. |
| Плитка | `/expenses` | Карточки в две колонки и фильтр по диапазону кодов с двойным слайдером. |

Два поля по предметной области: `expense_behavior` (`fixed` / `variable`) и целочисленный `expense_code`. Количество лайков вычисляется обработчиком как длина `expense_liked_by`.

Используемые коды счетов:

| Код | Назначение в учебной модели |
|---:|---|
| 20 | Основное производство |
| 25 | Общепроизводственные расходы |
| 26 | Общехозяйственные расходы |
| 44 | Расходы на продажу |

Коды основаны на [Плане счетов, утверждённом приказом Минфина России от 31.10.2000 № 94н](https://www.consultant.ru/document/cons_doc_LAW_29165/fd05066bbb0a451cf5dc95b2af35808cbef2509e/). Отнесение конкретных кофейных примеров к счетам сделано для учебного интерфейса и не заменяет учётную политику организации. Актуальная формулировка задания ЛР1 сверена с [репозиторием курса](https://github.com/iu5git/Web#лабораторные-2024).

## Первый запуск в Windows / PowerShell

Потребуются Python 3.12 и запущенный Docker Desktop с Linux-контейнерами.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если `.env` ещё нет, создайте его из примера и задайте свои данные MinIO:

```powershell
Copy-Item .env.example .env
```

Запустите MinIO и приложение из корня проекта:

```powershell
docker compose up -d
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

После запуска:

- [Лента](http://localhost:8000/expenses/feed)
- [Добавление](http://localhost:8000/expenses/draft)
- [Плитка](http://localhost:8000/expenses)
- [MinIO Console](http://localhost:9001)

Адрес `/` и страницы документации API отключены намеренно: в лабораторной используются ровно три прикладных GET-маршрута.

## Медиа и MinIO

MinIO API доступен по `http://localhost:9000`, консоль — по `http://localhost:9001`. Контейнер `minio-init` создаёт bucket `expense-items` и разрешает анонимное чтение.

В корне bucket должны находиться 14 объектов:

| Издержка | Изображение | Видео |
|---|---|---|
| Аренда кофемашины | `coffee_machine_rental.png` | `coffee_machine_rental.mp4` |
| Подписка для кассы | `cash_register_subscription.png` | `cash_register_subscription.mp4` |
| Кофейное зерно | `coffee_beans.png` | `coffee_beans.mp4` |
| Молоко | `milk.png` | `milk.mp4` |
| Бумажные стаканы | `paper_cups.png` | `paper_cups.mp4` |
| Крышки для стаканов | `cup_lids.png` | `cup_lids.mp4` |
| Порционный сахар | `sugar_sticks.png` | `sugar_sticks.mp4` |

Пример прямого URL: `http://localhost:9000/expense-items/coffee_beans.png`. FastAPI не проксирует медиа: браузер получает их напрямую из MinIO.

## Структура проекта

```text
main.py                       Создание FastAPI и подключение маршрутов
api/
  expense_handlers.py        Три GET-обработчика и фильтрация по кодам
data/
  expense_items.py           Коллекция издержек
templates/
  expense_base.html          Общий каркас и нижняя навигация
  expense_feed.html          Лента
  expense_draft.html         Черновик
  expense_tiles.html         Плитка и двойной слайдер
static/css/expenses.css       Стили фиксированного портретного интерфейса
docker-compose.yml            MinIO и настройка bucket
```

## Обработка запросов

- `GET /expenses/feed` открывает первую опубликованную издержку.
- `GET /expenses/feed?expense_id=3` открывает карточку с ID 3.
- `GET /expenses/feed?expense_id=6&next=true` открывает следующую карточку и после последней возвращается к первой.
- `GET /expenses/draft` показывает единственный черновик.
- `GET /expenses?min_expense_code=20&max_expense_code=26` оставляет коды от 20 до 26 включительно.

Значения фильтра сохраняются в элементах двойного слайдера после запроса. Нечисловые значения, обратный диапазон и выход за доступные границы возвращают HTML со статусом 400. Несуществующий или скрытый ID ленты возвращает HTML со статусом 404.

## Проверка перед защитой

1. Показать три страницы и соответствующие макеты Figma.
2. В DevTools → Network показать три GET-запроса, параметры `expense_id`, `next`, `min_expense_code`, `max_expense_code` и готовый HTML в Response.
3. Показать URL изображений и видео в коллекции и обращения браузера к MinIO на порту 9000.
4. В коде показать одну коллекцию, три обработчика и использование данных в трёх Jinja2-шаблонах.
5. Объяснить серверную фильтрацию и вычисление количества лайков.

Для остановки MinIO используйте `docker compose down` без `-v`, чтобы не удалить volume с медиа.
