# Техническое задание на систему Масштаб

## 1 Цель

Разработать систему с веб-сервисом, веб-приложением и нативным клиентом для публикации и просмотра карточек издержек с изображением и коротким видео. Поля предметной области: `cost_behavior` — постоянные/переменные издержки и `cost_code` — целый неотрицательный код издержки. Цена вместо кода не используется.

## 2 Назначение

Гость просматривает опубликованные издержки в списке и ленте, фильтрует их по коду. Создатель после входа дополнительно добавляет и публикует собственные издержки, логически удаляет свои записи, ставит и отменяет лайки. Кофейные издержки служат примерами данных; приложение описывает издержки в целом. Отдельная роль модератора не предусматривается.

## 3 Задачи

3.1 Разработать дизайн трёх страниц, серверные шаблоны и фильтрацию по коду издержки — Figma, FastAPI, Jinja2, HTML, CSS, MinIO, Docker — ЛР1.

3.2 Создать таблицы издержек, пользователей и лайков; реализовать создание, публикацию и логическое удаление — PostgreSQL, SQLAlchemy, Alembic, Adminer — ЛР2.

3.3 Разработать REST API двух доменов costs/users из десяти методов, загрузку файлов изображения/видео в MinIO и проверку запросов — FastAPI, Pydantic, Postman — ЛР3.

3.4 Добавить аутентификацию, авторизацию, cookie-сессии Redis, Swagger и подготовить ТЗ — FastAPI, PBKDF2, Redis, OpenAPI, Word — ЛР4.

3.5 Разработать гостевые страницы списка и ленты с mock-данными — React, TypeScript, Vite, React-Bootstrap — ЛР5.

3.6 Подключить четыре страницы к API, реализовать вход, создание, удаление и лайки — Redux Toolkit, redux-thunk, Axios, кодогенерация OpenAPI — ЛР6.

3.7 Реализовать хранение фильтров, адаптивность, PWA, сборку Tauri и HTTPS — Redux Toolkit, CSS, PWA, Tauri — ЛР7.

3.8 Разместить демонстрационный React-клиент с mock-данными на GitHub Pages. Статический Pages не заменяет сервер FastAPI.

3.9 Подготовить РПЗ, ТЗ, таблицу методов и ER/UML-диаграммы — Word, StarUML; все диаграммы хранить в одном проекте.

3.10 Вести репозитории бэкенда и фронтенда с отдельной тематической веткой для каждой лабораторной — Git, GitHub. Дополнительный асинхронный сервис в объём ТЗ не входит.

## 4 Функциональные требования

### 4.1 HTTP методы

4.1.1 GET `/api/costs` — список опубликованных издержек, диапазон `min_cost_code`/`max_cost_code`, признак `is_owner` 0/1.

4.1.2 GET `/api/costs/feed` — первая карточка без ID, выбранная с `cost_id` или следующая с `cost_id` и `next=true`; `is_liked` 0/1.

4.1.3 GET `/api/costs/draft` — единственный черновик текущего пользователя, ID не передаётся.

4.1.4 POST `/api/costs` — создание черновика: `cost_name`, файлы `image`, `video` (multipart/form-data).

4.1.5 PUT `/api/costs/{cost_id}` — публикация своего черновика: `cost_description`, `cost_behavior`, `cost_code` (JSON).

4.1.6 DELETE `/api/costs/{cost_id}` — логическое удаление своей карточки. Строка и медиа остаются.

4.1.7 POST `/api/costs/{cost_id}/likes` — свой лайк: JSON `is_liked=1` ставит, 0 отменяет.

4.1.8 POST `/api/users` — регистрация: `user_name`, `password`; хеш пароля хранится в БД.

4.1.9 POST `/api/users/auth` — аутентификация: `user_name`, `password`; выдача cookie и создание сессии Redis.

4.1.10 POST `/api/users/logout` — удаление сессии и cookie.

### 4.2 Меню

4.2.1 Нижняя панель на всех страницах содержит Ленту издержек, Добавление издержки, Список издержек и Вход.

4.2.2 Гость открывает список, ленту и вход. Добавление доступно создателю. У создателя Вход заменяется на Выход с вызовом 4.1.10; после выхода состояние и фильтр сбрасываются.

### 4.3 Вход пользователя

4.3.1 Страница содержит поля `user_name`, `password`, кнопки Войти и Зарегистрироваться, вызывающие соответственно 4.1.9 и 4.1.8. После входа открывается список издержек в режиме создателя.

4.3.2 Cookie содержит случайный токен, а не ID пользователя. Redis связывает хеш токена с ID и TTL 3600 секунд. Cookie имеет HttpOnly, SameSite=Lax; для HTTPS включается Secure. Неверный пароль даёт 401, занятое имя — 409.

### 4.4 Список издержек

4.4.1 Доступен гостю и создателю. Карточки в двух колонках содержат изображение, название, код и число лайков; данные загружаются методом 4.1.1.

4.4.2 Числовые границы и двойной слайдер с кнопкой применяют фильтр `min_cost_code`/`max_cost_code` на сервере; пустые границы не ограничивают выборку. Нажатие на карточку открывает ленту через 4.1.2 с её ID.

4.4.3 У собственной карточки (`is_owner=1`) создателю доступно Удалить, вызывающее 4.1.6. Отдельной страницы удаления нет.

### 4.5 Лента издержек

4.5.1 Доступна гостю и создателю. Показывает одну опубликованную карточку через 4.1.2: видео, название, описание, код и тип издержки, число лайков.

4.5.2 Описание свёрнуто до двух строк, Ещё раскрывает текст. Параметры находятся под привычной иконкой справа; справа также лайк. Следующая карточка загружается через `cost_id` и `next=true`, по кругу.

4.5.3 Лайк доступен создателю и вызывает 4.1.7 с `is_liked=1`/0. Гость лайки не изменяет.

### 4.6 Добавление издержки

4.6.1 Доступно создателю. При открытии метод 4.1.3 загружает собственный черновик. У пользователя не более одного черновика.

4.6.2 Если черновика нет, вводятся только три поля: название, изображение и видео. Кнопка Далее вызывает 4.1.4; файлы сохраняются в MinIO, URL — в БД. `cost_creator_id`, ID, статус draft и дата создания назначаются сервером.

4.6.3 Для черновика вводятся только три поля публикации: описание, тип издержки и код. Опубликовать вызывает 4.1.5, ID берётся из ответа черновика. Системные даты, пользователь, статус, URL и лайки не являются входными полями этой формы.

4.6.4 Разрешены переходы draft → published, draft → deleted, published → deleted. Обратного перехода нет. Удалённые записи не передаются клиенту. Без сессии изменение даёт 401, чужой или уже опубликованный черновик — 404, неверные поля — 422.

## 5 Требования к аппаратному обеспечению

5.1 Для учебного сервера совместного размещения API, PostgreSQL, Redis и MinIO: 64-разрядный процессор с четырьмя логическими ядрами, 16 ГБ ОЗУ, не менее 20 ГБ свободного SSD. Это начальная конфигурация стенда, не результат нагрузочного теста; расчёт по RPS и приросту БД выполняется в ЛР5.

5.2 Для клиента: компьютер или мобильное устройство с современным браузером, не менее 4 ГБ ОЗУ и доступом к сети сервера. Для загрузки файлов нужен доступ к локальному хранилищу. Сервер и клиент учебного стенда могут работать на одном компьютере.

## 6 Требования к программному обеспечению

6.1 Сервер: Windows 10/11 с Docker Desktop либо Linux с Docker Engine и Compose v2; Python 3.12, FastAPI 0.141.1, Uvicorn 0.52.4, SQLAlchemy 2.0.44, Alembic 1.17.1, asyncpg 0.30.0, pydantic-settings 2.11.0, redis-py 5.2.1. Точные зависимости закреплены в requirements.txt. PostgreSQL 15 и Redis 7 развёрнуты контейнерами; образы MinIO и Adminer заданы в docker-compose.yml.

6.2 Будущий клиент: Node.js 22 LTS, React 19, TypeScript 5, Vite 7, Redux Toolkit 2, Axios 1, React-Bootstrap 2, Bootstrap 5, Tauri 2. Это требования к последующим лабораторным, не перечень установленного в ЛР4 фронтенда. Браузер — актуальный Chrome, Edge или Firefox с JavaScript и cookie.

6.3 Средства разработки: Git 2, VS Code, StarUML с ER и Sequence, Postman либо Insomnia. Swagger UI — `/docs`, схема OpenAPI — `/openapi.json`. Локальный HTTP использует cookie Secure=false, при развёртывании HTTPS — Secure=true.
