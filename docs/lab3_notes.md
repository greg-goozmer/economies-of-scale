# ЛР3: конспект лекций 3–5 и контрольные вопросы

## Короткий конспект

Лекция 3: Agile организует работу короткими итерациями; каждая лабораторная — отдельный этап и ветка Git. UML-диаграмма классов показывает сущности, их поля, методы и зависимости. В данной работе страницы будущего фронтенда зависят от доменов `CostApi`/`UserApi`, домены — от сериализаторов и моделей БД.

Лекция 4: HTTP работает по схеме запрос–ответ поверх сетевого стека. Запрос содержит метод, URL, заголовки и при необходимости тело; ответ — код состояния, заголовки и тело. В сервисе `GET` читает, `POST` создаёт или выполняет действие, `PUT` публикует, `DELETE` логически удаляет. HTTPS — HTTP через TLS.

Лекция 5: веб-сервис отдаёт данные, а не HTML-страницы. REST привязывает ресурсы к URL и использует семантику HTTP-методов; JSON передаёт поля данных. В ЛР3 запросы проверяются коллекцией Postman, а Swagger и реальная авторизация относятся к ЛР4.

## Ответы на контрольные вопросы

1. **Веб-сервис:** серверное API, к которому другие приложения обращаются по сети. Наш `/api` отдаёт JSON из PostgreSQL и сохраняет файлы в MinIO.
2. **REST:** стиль API с ресурсными URL, стандартными методами HTTP и передачей представления ресурса. Например, `GET /api/costs` читает, `DELETE /api/costs/{id}` удаляет логически.
3. **RPC:** удалённый вызов функции/процедуры. В отличие от REST, главным становится действие, а не ресурс и его представление.
4. **Заголовки и методы HTTP:** заголовки описывают запрос/ответ (`Content-Type`, `Accept`); методы задают действие (`GET`, `POST`, `PUT`, `DELETE`). В ЛР3 загрузка файлов использует `multipart/form-data`, остальные изменения — JSON.
5. **Версии HTTP:** HTTP/1.1 использует постоянные соединения, HTTP/2 — мультиплексирование потоков, HTTP/3 работает поверх QUIC/UDP. Смысл методов и статусов сохраняется.
6. **HTTPS:** защищённый TLS-вариант HTTP; шифрует трафик и проверяет подлинность сервера по сертификату.
7. **OSI ISO:** семиуровневая модель взаимодействия сетей. HTTP относится к прикладному уровню, TCP/UDP — к транспортному, IP — к сетевому.

## Привязка к проекту

`api/cost_api.py` содержит семь методов домена издержек, `api/user_api.py` — три метода пользователей. `schemas/` проверяет и сериализует данные, `models/` описывает три таблицы через ORM. `api/current_user.py` возвращает фиксированный ID создателя через singleton-кеш — это требование только ЛР3, а не авторизация. `docs/costs_database.mdj` содержит ER- и UML-диаграммы.
