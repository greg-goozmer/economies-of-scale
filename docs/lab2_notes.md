# ЛР2: конспект и контрольные вопросы

## Короткий конспект лекции 2

Реляционная база хранит данные в связанных таблицах. ER-диаграмма показывает сущности, их атрибуты, первичные и внешние ключи, а также кратности связей. Нормализация уменьшает дублирование данных. Тип и длина каждого поля должны соответствовать смыслу данных; даты хранятся типом даты и времени.

SQL включает DDL для структуры, DML для данных, DCL для прав и TCL для транзакций. Логическое удаление меняет статус строки, поэтому связанные данные не теряются. Adminer — административный интерфейс, а обычное приложение работает с БД через отдельное подключение.

Миграции последовательно изменяют структуру БД. Alembic хранит DDL-миграции, SQLAlchemy описывает модели и выполняет ORM-запросы. Параметры подключения берутся из окружения. В трёхслойном SSR-приложении браузер обращается к FastAPI, сервер получает данные из PostgreSQL и формирует HTML через Jinja2.

## Ответы на контрольные вопросы

1. **Какие бывают БД?** Реляционные, документные, ключ-значение, графовые и другие. В работе используется реляционная PostgreSQL.
2. **Что такое SQL?** Язык определения структуры, чтения и изменения данных, управления правами и транзакциями в реляционной БД.
3. **Что такое курсор?** Механизм последовательной обработки результата SQL-запроса. В прикладном коде сырой SQL выполняется соединением/сессией, которые передают запрос драйверу БД.
4. **Что такое ORM?** Сопоставление таблиц с классами, а строк — с объектами. Оно позволяет формировать запросы средствами языка программирования.
5. **Чем модель отличается от миграции?** Модель описывает ожидаемую структуру для приложения, а миграция — конкретный переход реальной схемы БД из одной версии в другую.
6. **Зачем нужна чистая архитектура?** Чтобы разделить представление, прикладную логику и работу с данными, снизить связанность и упростить изменения и тестирование.

## Привязка к проекту

- PostgreSQL — хранилище.
- `models/` — ORM-модели.
- `alembic/versions/` — DDL-миграции.
- `api/expense_handlers.py` — HTTP-методы и DML.
- `templates/` — серверное представление.
- Логическое удаление выполнено сырым `UPDATE`, создание и публикация — ORM.
