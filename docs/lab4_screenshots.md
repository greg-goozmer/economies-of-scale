# ЛР4 Девять скриншотов для защиты

Используйте **localhost:8000 во всех окнах**. API должен быть запущен из ветки authentication, а Docker — содержать PostgreSQL, MinIO и Redis. Не используйте старые запросы ЛР3 с фиксированным пользователем.

## Подготовка один раз

1. Откройте Chrome/Edge в инкогнито: Ctrl+Shift+N. Перейдите на http://localhost:8000/docs.
2. В users → POST `/api/users` нажмите Try it out. Вставьте `{"user_name":"student4","password":"Lab4-demo-2026!"}` → Execute. Нужен 201. Если 409, имя уже существует: используйте свой известный пароль либо новое имя; не меняйте чужие записи.
3. Для Postman нажмите Import → Select files и выберите `docs/postman/lab4_costs.postman_collection.json`. Путь нельзя вставлять как cURL. В коллекции есть переменные `base_url`, `cost_id`, `session_cookie`. В `session_cookie` вставляется **только значение** cookie, без `cost_session=`.
4. В запросах коллекции отключено автоматическое cookie-хранилище (`disableCookies=true`): авторизация идёт явным заголовком Cookie. Для проверки гостя не включайте этот заголовок. Не используйте Authorization или вкладку Cookies.

## Рисунок 1 Аутентификация через Swagger

В users → POST `/api/users/auth` → Try it out вставьте тот же JSON с именем и паролем → Execute. Снимите URL, два входных поля и ответ **200**, `user_id`, `user_name`. Не снимайте большую свёрнутую страницу со всеми методами. На скрине должно быть видно, что запрос выполнен, а не только пример схемы.

## Рисунок 2 Получение списка через Swagger

В costs → GET `/api/costs` → Try it out: `min_cost_code=20`, `max_cost_code=40` → Execute. Браузер сам отправит cookie входа. Снимите два параметра, URL с query и 200 с началом списка. Если список пуст, временно уберите границы. `is_owner` у чужих карточек будет 0 — это правильно.

## Рисунок 3 Перенос cookie из браузера в Postman

В том же окне инкогнито нажмите F12 → Application (если не видно, меню `»` справа во вкладках) → Storage → Cookies → `http://localhost:8000`. Выберите строку `cost_session`, скопируйте Value. В Postman в Headers добавьте строку: Key `Cookie`, Value `cost_session=СКОПИРОВАННОЕ_ЗНАЧЕНИЕ`, галочка слева включена. Можно вставить Value в переменную коллекции session_cookie — готовые запросы используют `cost_session={{session_cookie}}`. Снимите Application со строкой cookie и/или Headers Postman, чтобы был виден именно перенос cookie. Реальную cookie не публикуйте в GitHub.

## Рисунок 4 Список в Postman с cookie

Откройте «04 Список с cookie». GET `http://localhost:8000/api/costs?min_cost_code=20&max_cost_code=40`. Headers: Cookie с включённой галочкой → Send. Снимите URL, заголовок и ответ 200. Это чтение для вошедшего пользователя.

## Рисунок 5 Тот же список без cookie

Откройте «05 Список без cookie». Тот же GET, но строка Cookie отсутствует/выключена. Send → тоже **200**. Снимите Headers и ответ. Это доказывает, что чтение доступно гостю. Если вы создали другой запрос вручную, убедитесь, что в Settings включено Disable cookie jar.

## До рисунков 6 и 7 Получить собственный черновик

Откройте «Подготовка — свой черновик» GET `http://localhost:8000/api/costs/draft` с cookie. Если ответ объект — используйте его `cost_id`. Если `null`, выполните «Подготовка — создать черновик»: POST `http://localhost:8000/api/costs`, Headers Cookie включён; Body → form-data, **ровно три строки**:

| Key | Тип | Value |
|---|---|---|
| cost_name | Text | Аренда кофемашины ЛР4 |
| image | File | Выбрать `docs/postman/fixtures/example_cost.png` |
| video | File | Выбрать `docs/postman/fixtures/example_cost.mp4` |

Тип File выбирается в выпадающем меню справа от Key. Content-Type вручную не задавайте: Postman добавит boundary. Send → 201. `cost_id` из ответа переносится в переменную коллекции автоматически; проверьте его. **Не используйте старую опубликованную карточку 14 или чужой ID.** Ошибка 409 означает, что свой черновик уже есть: получите его GET draft, не создавайте второй.

## Рисунок 6 Гость не может публиковать

«06 Публикация без cookie»: PUT `http://localhost:8000/api/costs/{{cost_id}}`, без Cookie. Body → raw → JSON:

```json
{
  "cost_description": "Постоянные издержки на аренду оборудования",
  "cost_behavior": "fixed",
  "cost_code": 31
}
```

Send → **401 Authentication required**. Снимите URL с настоящим числом, все три входных поля и статус 401. Не снимайте 404: это не доказательство проверки гостя.

## Рисунок 7 Создатель публикует

«07 Публикация с cookie»: тот же PUT, тот же ID и три поля, но Headers Cookie включён. Send → **200**. Снимите Body запроса сверху и начало ответа снизу: `cost_id`, `cost_description`, `cost_status: published`, `cost_behavior`, `cost_code`, по возможности `cost_formed_at`. Выходных полей 14, вводить все их не нужно. Повторная публикация уже опубликованной карточки даст 404 — для повторного показа создайте новый черновик.

## Рисунок 8 Пользователь в сессии Redis

Откройте терминал VS Code в корне проекта. Выполните:

```powershell
docker compose exec redis redis-cli --scan --pattern 'cost_session:*'
```

Скопируйте **целый ключ** `cost_session:...` и подставьте вместо KEY:

```powershell
docker compose exec redis redis-cli GET KEY
docker compose exec redis redis-cli TTL KEY
```

Снимите три команды и результаты: GET — числовой ID пользователя, TTL — положительное количество секунд. Сравните ID с ответом входа на рисунке 1. При нескольких ключах определите свой через команду `python -m tools.inspect_cost_session`: вставьте cookie скрытым вводом, программа выведет только хеш-ключ, ID и TTL. После logout ключ будет удалён; при истечении часа войдите снова и скопируйте новую cookie.

## Рисунок 9 Signature в StarUML

Откройте `docs/costs_database.mdj`, в Model Explorer раскройте Cost publication scenario → Публикация и просмотр издержки → Lab4 sequence (A4). Выберите **сплошную стрелку запроса**, например PUT публикации. В Property Editor справа найдите `signature`: должна быть ссылка на операцию **PUT /api/costs/{cost_id}** класса CostApi, а не просто текст имени стрелки. Ниже `arguments` содержит входные поля. Снимите диаграмму и панель свойств вместе. Если панель скрыта: View → Editors → Property Editor (или View → Property Editor, в зависимости от версии).
